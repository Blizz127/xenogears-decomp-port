# Xenogears host ABI generator

This directory generates the US Disc 1 battle bridge include and the native storage declarations used by the v0.7.93 preview. The driver runs offline with Python 3.8 or newer. Its inputs are text files. The Linux and Windows builds use identical generated bytes.

## Prepare the symbol files

Extract `disc/battle.bin` from your own US Disc 1 with the public project's overlay extractor. The expected file is 343,936 bytes with SHA-256 `1830b4ef1fe37129972fc310dfad534f8161d6c0b123e74254c3711334a3e291`.

```sh
mkdir -p disc
python3 tools/scripts/extract_overlays.py "/path/to/your/Disc 1.bin" --extract-to disc
```

Use the project's Splat installation (verified with splat64 0.33.2 and spimdisasm 1.33.0) and the following four files from the same checkout as the generator. Keep their relative paths and LF line endings.

- `config/battle.yaml`
- `config/symbol_addrs.battle.txt`
- `config/symbol_addrs.slus_006.64.txt`
- `tools/splat_ext/scommon.py`

From the directory containing `config` and `disc`, run the split locally. Keep the extracted disc data and Splat's generated assembly and assets in your local build directory. The host build reads the two generated linker symbol lists.

```sh
splat split config/battle.yaml
```

The driver verifies the main symbol catalog and both generated lists against the profile. The split and US executable symbol assignments can be checked against the public revision. [Public split configuration](https://github.com/Blizz127/xenogears-decomp-port/tree/7c729166cbcf076cd5a30872a7022171fc7f6bbb/config)

## Call the generator from a build

In the examples, run from the split directory and set `driver` to the location of this directory's `generate.py`. On Windows, use `py -3` in place of `python3` and pass the same arguments.

```sh
driver=/path/to/public-generator/generate.py
python3 "$driver" bridge --phase cold \
  --main-symbols config/symbol_addrs.slus_006.64.txt \
  --battle-functions linker/undefined_funcs_auto.battle.txt \
  --battle-symbols linker/undefined_syms_auto.battle.txt \
  --out build/battle_bridge_map.inc
```

Use this include when compiling the native objects for the first link. Pass the sorted unique missing symbol names reported by that native trial link, one per line, as `build/undef.txt`. The driver verifies the entire set before emitting a declaration. A changed ABI requires a reviewed profile update.

```sh
python3 "$driver" stubs --undefined build/undef.txt --out build/stubs.c
python3 "$driver" bridge --phase settled \
  --main-symbols config/symbol_addrs.slus_006.64.txt \
  --battle-functions linker/undefined_funcs_auto.battle.txt \
  --battle-symbols linker/undefined_syms_auto.battle.txt \
  --out build/battle_bridge_map.inc
```

Compile the generated declarations and recompile the native translation unit that consumes the settled bridge before the final link. The Windows build can consume the same settled include and declarations generated on Linux. Both generation phases run before an executable is available if the native link's undefined-name list is already available.

## Provenance

The 606 additional function labels in `host-abi.json` were identified from a Splat split of a legally supplied US `SLUS_006.64` using public symbol assignments. The project's published native Linux bridge independently confirmed the same function classifications.

The 467 storage symbols and their byte extents came from the public Linux executable's ELF object-symbol records, using the missing names reported by the native trial link. The 171 settled storage extents and 265 additional split-object sizes were observed in its named host binding table. The extracted executable had SHA-256 `1524ca4ff975f202f5a5a179537765d05fcbd84328f462d32d93c46c0fce266c`. These observations are included as facts in the profile, so generation needs only the local symbol lists and Python. [v0.7.93 preview release](https://github.com/Blizz127/xenogears-decomp-port/releases/tag/v0.7.93-preview)

The emitted C formatting and `stubs.c.in` preserve the project-authored output contract of `gen_battle_bridge_map.py` and `gen_port_stubs.py`, including the port's stub-reporting and lookup helpers. The profile contains symbol names, type classifications, byte counts and input digests.
